# 足場積算アプリ 仕様書 ＆ 今後の方針

戸建・くさび式足場の積算＋割り付け図＋見積書ツール。位置づけは **AshiBase（資材管理・リリース済）への流入装置**。割り付け・積算・図解は無料開放、見積書PDF（画像）化のみ課金。実装ファイルは `AshiBaseSekisan.jsx`（単一Reactコンポーネント）。

---

## 0. 位置づけ・方針

- 割り付け・積算・図解・延べ面積は**無料**。見積書の画像出力のみ**有料（初回3クレジット・3回まで無料）**。
- 積算数量を **AshiBase資材管理へ接続**（積算→資材管理に数量を流し込む）。
- まず戸建住宅向けに特化。くさび式 A/B 両対応。4面一気に算出（部分組立＝1〜3面も対応）。

---

## 1. 入力

- **タイプ**：A（コマ450／階高1800）／B（コマ475／階高1900）
- **建物・高さ**：軒天高（＝雨樋高、水切り〜軒天の寸法）／基礎高（水切り〜地面）／屋根作業の有無／各段手摺の本数（1本 or 2本、既定1）／昇降階段の設置有無
- **各面（北・東・南・西）**：長さ／軒の出／敷地幅
  - 長さ未入力（空/0）の面は**組立しない**ものとして全計算から除外（部分組立）。

---

## 2. 高さ → 支柱（検証済みロジック）

- コマ＝A:450 / B:475。階高＝A:1800 / B:1900。**支柱はコマ数で管理**（3600=8／2700=6／1800=4／900=2／450=1コマ）。
- **通常支柱は最下部コマの下に「下駄」あり：A=240mm／B=475mm**（根がらみ支柱は下駄なし）。
- **オフセット** = 軒天高 mod 階高（＝軒天から1800を引いていった残り）。最下部コマは「水切り＋オフセット」の高さ。
- **ジャッキ**：基本600、上げ量は最大400程度に抑える。ジャッキも足場高さに含む。
  - ジャッキ上げ ＝ 基礎高 ＋ オフセット − 下駄。
  - 上げが過大（>400）なら オフセットを 450（1コマ）ずつ下げる。
  - 上げが負になる（基礎高が下駄より小さい 等）→ **根がらみ支柱が必要**（A=08/740mm、B=1425）。要否は高さ計算の結果で決まる。
- **最上段踏板 ＝ 軒天高 − 階高**（A:−1800／B:−1900）。踏板段数もここから。
- **支柱総高（地上から）** ＝ 基礎高 ＋ 軒天高 ＋（屋根作業なら+900）。
- **屋根作業**：軒天+900に**落下手摺2本**を追加、支柱もその分（+900）高くする。
- **支柱構成**：必要コマ数を満たす**最小本数**の組合せ（例：15コマ→8+8＝16、余り1コマ許容）。
- **外柱／内柱**：外柱は全高。**内柱は最上段踏板まで**の短い別構成（手摺・落下手摺分は立てない）。

---

## 3. 離れ配分（本ツールの核心価値）

**「4面組む時、建物寸法と敷地幅を測って離れは幾つか」を即解消する。**

- ある面の離れは、その面だけでは出ない。**直交面の割り付け総長 − 建物寸法 ＝ 総オーバーハング** を配分して決まる。
- **離れの目標＝軒の出+100前後**（近すぎ遠すぎNG）、下限＝軒の出（軒をかわす）、上限＝敷地幅−70（ジャッキベース140の半分）。
- 割り付けは「建物＋目標離れ」の**最近傍**に丸める。過大な尾（200等）は落として離れを膨らませない。
- **表示離れ＝割り付けの実オーバーハング（足場合計−建物）** で割り付けと一致させる。
- 両側組立は理想離れの比で配分。**片側のみ組立は組立側に全振り・開放側0**（部分組立で外へ大きくはみ出さない＝倒壊防止）。
- **600幅を優先**：軒出+100が600以下でも、敷地が許せば+300伸ばして600超（＝600幅足場）にする。400幅は敷地が厳しい時だけ。
- **足場幅の判定＝実オーバーハング（離れ）が700mm以下なら400幅、700mm超で600幅**。
- 角の共有支柱は方向ごとに別の離れを持つ。

---

## 4. 横方向の割り付け

- 標準スパン：1800/1200/900/600（1500は避け900+600）。600以下の調整材：A=400/300/200、B=350/150。
- **1800を最大化**（1200+1200+900 でなく 1800+900+600）。調整材の小片より標準スパンの組合せを優先。
- 面リストの「L=」は**足場長（スパン合計）**を表示（建物長ではない）。
- 敷地幅が厳しく離れの上限＝下限（ぴったりこの値限定）になった場合、標準スパン＋調整材の組合せでその値を厳密に作れないことがある。その場合は割付ゼロにはせず、制約を外してtargetに最も近い組合せへフォールバックする。

---

## 5. 部材の数え方（一側足場＝内柱2スパンに1本）

一側足場：手摺類は**外側のみ**でスパン数対応。

- **外柱本数**：閉じた4面＝総スパン数。部分組立＝総スパン数＋開放端ぶん。
- **内柱本数** ＝ Σ各面 floor((スパン−1)/2)（内部内柱） ＋ 開放端数（片側だけ組立の角）。図解表示と一致。
- **支柱（サイズ別）**：外柱＝全高構成、内柱＝最上段踏板までの構成。サイズ別に集計（36支柱・18支柱・09/095支柱 等）。根がらみ支柱は必要時のみ。
- **踏板**：足場幅で幅が決まる。600幅→400幅踏板（4018/4012/4009/4006）、400幅→250幅踏板（2518/2512/2509/2506/2004）。**角に600スパンが入る場合は4006踏板は不要→踏板受けは600手摺（踏板用の06手摺）**。
- **手摺（根がらみ＋各段＋落下を長さ別に合算）**：外周＝スパンごとに 根がらみ1＋各段×本数＋落下2（屋根作業時）。長さ別（18/12/09/06…）。
- **内柱連結手摺**（600幅→06手摺／400幅→04手摺）＝ 内柱箇所 ×（1＋段数）。
- **大ブラ／小ブラ**（600幅→大／400幅→小）＝ **外柱-only（外柱本数−全内柱）× 段数**。内柱箇所は連結手摺が踏板を持つのでブラ不要。出隅は二重計上しない。
- **ジャッキ**：固定ジャッキ（平地用）＝外柱＋内柱の柱数。自在ジャッキ＝屋根上・斜め地盤用（平地は0）。壁当ジャッキ＝内柱数。壁当ホルダー＝壁当ジャッキ数。
- **ウルトラワイドベース**（アラオ製）＝固定ジャッキと同数。
- **火打**：1隅につき1本。火打＝4mパイプ＋自在クランプ2個セット（自在クランプ＝火打×2）。
- **筋交（18ブレス）**：各面6スパン未満は3本、6スパン以上は3+(スパン−5)本。＋階段1本につき1本。
- **メッシュシート**：1スパンに縦張り（幅＝スパン、長さ6.3m等）。余りは横張り用として別表示（未反映＝要検証）。
- **昇降階段（設置ON時）**：段数＋（屋根作業で+1）。さらに固定ジャッキ+3／外柱支柱（計算構成）+3／18手摺+11／12手摺+3／06手摺+19／09支柱+3（Bは095支柱+3）／大ハネ+3／4018+1 を追加。
- **ピン類（大/小/02）**：ハネ出し用（ハネ出しが無ければ0）。※本数ルール＝要検証。

## 6. 図解

- **高さ断面図**：地面・基礎・水切り・軒天・軒の出を再現。足場側はジャッキ上げ・支柱・コマ（緊結部ティック）・各段手摺（🟡）・天端手摺・落下手摺（屋根作業時、軒天+450/+900に🟡）。寸法（基礎・軒天・離れ・足場高・オフセット）記入。※軒天レベルの天端手摺マークは出さない。
- **平面 割り付け図（4面）**：建物を中央に足場が四周。面ごとに離れを反映（開放側はギャップ0で建物端に密着、外へはみ出さない）。各スパンのサイズ・内柱位置（外柱対応の建物側）を表示。寸法（建物・各面離れ）記入。
- **延べ面積** ＝ 足場外周（組立面のスパン合計）× 足場高。

## 7. 見積書・課金

- 見積書は客先提出用。**自社情報は設定機能で事前入力・保存**（自社名・住所・電話・担当）→見積書に自動反映。宛先・現場・単価は都度入力。設定の保存・見積書PDF化はいずれもLINEログイン必須（積算本体の計算・割り付け・図解はログイン不要）。
- 金額＝**延べ面積 × ユーザー任意の単価**（足場工事一式）。**明細はユーザー追加可**（シート・昇降階段など：品名・数量・単価）。
- 内訳：**小計（税抜）→ 値引き → 税抜価格 → 消費税(10%) → 総額**。
- **値引き**：任意の値引額＋**自動丸め（切り下げ）**（総額を 0/00/000/0000＝10/100/1000/10000 単位に）。丸めで落ちた端数も値引きに含める。
- フォーマットは全ユーザー統一。無料中は**AshiBase署名＋QR**をフッターに。
- **出力＝画像（データ）共有**：見積書をcanvas画像に描画→ navigator.share でファイル共有／画像保存。テキスト共有ではない。
- **課金**：無料枠は**毎月自動で最大3回まで**（暦月でリセット、LINEアカウント＝Supabaseユーザーに紐付けてサーバー側で管理）。**月額・年額プランはPDF作成回数無制限**。AshiBase資材管理の課金とは完全に別管理。UIのalertは環境で効かないことがあるので画面内メッセージで表示。

## 8. 今後の方針（Claude Code 側で）

1. **リポジトリに commit**（`AshiBaseSekisan.jsx`）。
2. **Vite等でアプリ化 → 自ドメインにHTTPSデプロイ**。
   - これで **LINEへの画像ファイル共有が実機で通る**（コードは正しい。今プレビューで効かないのはサンドボックスiframeの権限制限のためだけ。書き換え不要）。
3. **認証：LINEログイン**。会社名等の入力を求めない最小サインアップとする。Supabase AuthにLINEは標準プロバイダーが無いため、フロントでLINE LoginのIDトークンを取得→Edge FunctionでLINE側を検証しSupabaseユーザーを発行（LINEのuser id (`sub`) を `user_metadata.line_user_id` 等に保存）という構成にする。
4. **AshiBase資材管理との関係**：リリース時点では別アプリとして運用（Supabaseプロジェクトも別）。資材管理側は既にLINE認証のため、LINE user idが一致すれば自動的にアカウントが紐付く（連携用の追加UIは不要）。課金・クレジット残数は両アプリで完全に別管理とし、連動させない。将来、積算数量→資材管理への連携APIを実装する際もLINE user idをキーに紐付け先アカウントを特定する。
5. **課金の本番化**：積算側で独自のクレジット/サブスク管理を実装（AshiBase側の課金とは独立）。QRを実URL・実画像に差し替え。
6. **要検証の詰め**：メッシュ横張り余り、ハネ出し時のピン本数。実物件1〜2棟で全項目の答え合わせ。
